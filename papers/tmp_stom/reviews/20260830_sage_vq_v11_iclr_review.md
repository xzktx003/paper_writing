# SAGE-VQ V11 独立 ICLR 风格评审

评审时间：2026-08-30

稿件：`papers/paper_zh_v11.md`

建议：**5.5 / 10，Borderline Reject**
置信度：**4 / 5**

## 1. 工作概述

本文研究约 2.12 bpp 的 block-scaled shared-codebook VQ 中，离散 assignment 是否能够叠加到已经任务适应的 scale 硬端点。前一版本观察到，聚合梯度在 98.20% 的六维向量上都能从当前码字的 8-way 邻域找到负一阶候选，但两轮八个真实 hard projection 全部退化。V11 将完整训练集确定性划分为四个任务分层互斥视图，只保留在所有视图中都预测下降的同一邻居，并按最差视图分数选择。候选率由 98.1973% 降到 48.7101%，最佳 changed endpoint 相对 V10 提高 2.2656 个百分点，但仍低于 scale baseline 2.4219 个百分点；因此系统安全回滚为精确 no-op。

本文不把这一结果包装为新 SOTA，而将其解释为一个代理失效边界：跨视图符号冲突是聚合一阶 proposal 的真实误差源，却不是全部误差；符号一致仍不能覆盖有限码字步的曲率及集合交互。

## 2. 优点

1. **假设可证伪，且干预最小。** V10 提出“曲率或梯度一致性”两种解释，V11 只改变 proposal 的信息结构，保持数据总量、训练、投影和 Gate 不变。98.20→48.71→0/8 的漏斗直接回答了梯度冲突是否存在以及是否足够解释失败。
2. **负结果报告严谨。** 论文明确区分“共识改善 changed endpoint”和“最终方法没有改善”，也明确 `audit_gate_passed=false` 是没有候选取得审计资格，而不是审计拒绝了某个已选端点。
3. **部署状态合同很强。** Assignment、scale、codebook、normalizer、固定元数据、逻辑码率和非目标状态均被逐项验证；最终 reconstruction 最大误差为零。输出文件哈希变化与逻辑张量相同也被正确区分。
4. **实验口径诚实。** 最终 PPL/六任务指标被标为同一 scale 部署状态的既有正式测量复用，而非新 benchmark。任务监督与 QTIP 通用 PTQ 的不公平性、任务 audit 的暴露边界、没有 kernel 等限制均主动披露。
5. **叙事明显成熟。** Block scale、Vector-GPTQ、Concrete 训练和 hard handoff 被组织为一条因果链，而不是并列声称四项创新；标题、摘要、方法公式、图和结论互相一致。

## 3. 主要问题

### 3.1 没有形成新的非零方法端点

从部署结果看，V11 最终仍是 V8 的 scale-only checkpoint。四视图共识是有诊断价值的 selector，但不是一个带来新 Pareto 点的方法。若按常规压缩论文评价，核心算法贡献和 headline 结果仍不足以支撑接收。

### 3.2 曲率结论仍是排除式推断

实验排除了“跨视图符号冲突足以解释失败”，但没有直接估计候选级 Hessian/Gauss--Newton 代价，也没有测量一阶、共识分数与真实单步或集合 hard loss 的排序相关。因而“剩余问题是曲率与集合交互”是合理推断，不是已经被分别识别的机制结论。

### 3.3 实验广度有限

正式机制实验只覆盖 Meta-Llama-3.1-8B-Instruct 的最后四层、固定 8-way 邻域、固定共享码本和一套目标任务监督。该范围足以否定当前具体 proposal，却不足以说明这一现象在不同模型规模、更多层、其他码本结构或 text-only 监督下普遍成立。

### 3.4 缺少同监督外部强基线

论文正确承认 QTIP、GSQ 与当前 task-adapted 结果不具备完全相同监督口径，但这也留下关键比较缺口：同一源 checkpoint、同一任务标签预算、同一可训练参数量下的离散/连续适应方法尚未复现。PV-Tuning 是最相关的方法先验，却没有统一实验对照。

### 3.5 统计强度与系统价值受限

每任务 31 条的 audit 较小，任务 baseline 又曾被 V10 读取，尽管 changed candidate 未接触它，仍削弱了“独立确认”的强度。论文报告逻辑 bpp，但没有压缩 kernel、实际显存占用或 token/s，因此不能把表示码率转化为系统收益。

## 4. 次要问题

1. 摘要数字较密，建议最终英文稿减少一个次要百分比，把空间留给“为何严格共识仍不足”的一句机制解释。
2. 正文应统一使用“领域”或“邻域”；当前核心数学对象实际是当前码字的局部邻域。
3. Figure 1 的右图若进入正式稿，建议给八个点标记 epoch/投影比例，或在图注中明确点序。
4. 参考文献中 2025/2026 工作需要在投稿时再次核对正式出版信息；当前不应依靠未来工作支撑优先权。

## 5. 可复现性检查

- 模型、层范围、码本维度和大小、group size、数据量、文本长度、epoch、LR、rate Gate、PPL 与六任务协议均已给出。
- 报告提供紧凑 JSON、原始 summary、checkpoint 和 token cache 哈希。
- 代码包含单卡 launcher、确定性分片、共识 selector、精确冻结和 38 项聚焦测试。
- 最终 no-op 的 benchmark 复用语义清楚。

不足之处是完整 checkpoint 和大日志不进入版本库，需要依赖报告中的本地路径和哈希；此外尚未提供公开环境中的端到端复现耗时分布。

## 7. 下一版必须完成的最小修复

下一版不应继续增加 view、epoch、seed 或扫描 projection ratio。唯一合理的完整实验前置门槛是一个便宜的候选级曲率排序 probe：

1. 在冻结 scale 的真实硬端点上，为有限数量的 layer/vector 与 8-way 邻居计算 scale-conditioned Hessian 或 Gauss--Newton 二阶分数；
2. 逐候选或小集合实际落盘并测量 hard validation loss，报告一阶分数、四视图 worst-case 分数、二阶分数与真实 loss change 的 rank correlation / top-k precision；
3. 只有二阶分数显著优于一阶与共识分数，才值得投入完整 assignment 训练；否则停止这条路线，将论文定位为极低比特 VQ 中代理失效和部署坐标边界的实证研究。

第二模型和同监督外部基线仍是最终投稿的必要条件，但它们应在出现非零可部署候选或明确转为诊断论文后再投入，以免重复一轮已被机制证据否决的昂贵训练。
