\section{Experiments}

\subsection{Experimental Setup}

% 模型与数据。主评测覆盖四个 Qwen3 模型和两个 Llama-3.1-Instruct 模型；Qwen3.8-27B 仅用于思考模式评测。
\paragraph{Models and data.} We evaluate Qwen3-4B, 8B, 14B, and 32B~\cite{qwen3}, as well as Llama-3.1-8B-Instruct and 70B-Instruct~\cite{llama3}. Qwen3.8-27B is evaluated separately with thinking enabled. Perplexity is measured on the full WikiText-2 test set with sequence length 2,048~\cite{wikitext}.
% 下游任务采用 lm-eval-harness 0.4.4 的零样本设置；只有带官方聊天模板的指令模型评测 IFEval。
We use LM Evaluation Harness v0.4.4~\cite{lmeval} for zero-shot ARC-Challenge, ARC-Easy, HellaSwag, LAMBADA OpenAI, PIQA, BoolQ, MMLU, and WinoGrande~\cite{arc,hellaswag,lambada,piqa,boolq,mmlu,winogrande}. IFEval is used only for instruction/chat models with an official chat template~\cite{ifeval}.

% 量化协议。主设置采用六维基础码字、4096 个码字和 12 位索引，对应 2 bit/weight 的索引码率。
\paragraph{Quantization protocol.} The main setting uses base-codeword dimension $d=6$, codebook size $K=4096$, and a 12-bit index, corresponding to an index rate of 2 bits per weight. One FP16 group scale is stored per 128 input columns, adding approximately 0.125 bit per weight.
% 每行每轮最多选择四个已有尺度组；这是搜索预算而不是额外存储的尺度数量。
Each round selects at most four existing scale groups per row (\texttt{groups\_per\_row=4}); this is a search budget, not the number of stored scales.
% 校准集由每个模型 320 条长度 4096 的 RedPajama-Data-1T 序列组成，随后在同一校准数据上做端到端尺度微调。
Calibration uses 320 RedPajama-Data-1T sequences of length 4,096 per model. We subsequently fine-tune scales end to end on the same calibration data. Baselines with fine-tuning are reproduced using their official implementations.

% 基线与硬件。质量评测比较 BF16、PV-Tuning、QuIP#、QTIP、NoWag、AQLM 和 LLVQ；除速度表外均在 A100-SXM4-80GB 上运行。
\paragraph{Baselines and hardware.} We compare BF16, PV-Tuning~\cite{pvtuning}, QuIP\#~\cite{quipsharp}, QTIP~\cite{qtip}, NoWag, AQLM~\cite{aqlm}, and LLVQ~\cite{llvq}. All quality evaluation and joint search run on NVIDIA A100-SXM4-80GB GPUs; Table~\ref{tab:throughput} uses an RTX 4090 Ada.

\subsection{Ablation Studies}

% 表 2 考察量化后端到端尺度微调的作用：在相同量化设置下，对比开启和关闭微调时四个 Qwen3 模型的 WikiText-2 困惑度及零样本准确率。
\paragraph{End-to-end scale fine-tuning.} Table~\ref{tab:finetuning} studies end-to-end scale fine-tuning after quantization. Under the same quantization setting, it compares WikiText-2 perplexity and zero-shot accuracy with and without fine-tuning for four Qwen3 model sizes.
\input{tab/finetuning}

% 四种模型规模在开启微调后均获得更低的 WikiText-2 PPL。除需核查的 PIQA 列外，其余准确率整体以小幅提升为主，但并非所有任务和规模都一致，例如 14B 的 HellaSwag 以及 8B、32B 的 WinoGrande 略有下降。PIQA 微调列与 LAMBADA 完全重复且和表 3 不一致，因此核实原始日志前不据此归纳。
Fine-tuning lowers WikiText-2 perplexity at all four model sizes. Excluding the PIQA column that requires verification, the reported accuracies mostly improve slightly, although the trend is not universal: HellaSwag decreases for 14B, and WinoGrande decreases for 8B and 32B. The fine-tuned PIQA values exactly duplicate LAMBADA and conflict with Table~\ref{tab:ablation}, so we draw no conclusion from that column before checking the raw logs.

% 表 3 消融尺度与码字分配两个优化对象。“×/×”“√/×”“√/√”分别表示均不优化、仅优化尺度、联合优化尺度与分配。由于未报告“×/√”，该表不能单独估计 Assign 的独立贡献。
\paragraph{Scale and assignment.} Table~\ref{tab:ablation} ablates scale and codeword-assignment optimization. The configurations $\times/\times$, $\checkmark/\times$, and $\checkmark/\checkmark$ denote no optimization, scale-only optimization, and joint scale-and-assignment optimization, respectively. Because $\times/\checkmark$ is not reported, this table cannot isolate the independent contribution of assignment optimization.
\input{tab/ablation}

% 从均不优化到仅优化尺度，Qwen3-4B/8B 的 PPL 分别从 22.69/14.41 降至 21.01/13.85；联合优化后进一步降至 12.18/9.76。联合优化提高 Qwen3-4B 的全部已列准确率和 Qwen3-8B 的多数准确率，但后者的 BoolQ 从 83.36 降至 80.55。
Moving from no optimization to scale-only optimization reduces Qwen3-4B/8B perplexity from 22.69/14.41 to 21.01/13.85; joint optimization further reduces it to 12.18/9.76. Joint optimization improves every listed accuracy for Qwen3-4B and most accuracies for Qwen3-8B, although BoolQ on Qwen3-8B decreases from 83.36 to 80.55.

% 表 4 在开启思考模式的 Qwen3.8-27B 上比较推理和代码能力。

\input{tab/qwen38}

% 本文相较两个量化基线取得更低 PPL，并在代码与知识推理任务上更高，但 BF16 仍然最好。
Our method improves PPL, LiveCodeBench v6, and GPQA-D over the two quantized baselines~\cite{livecodebench,gpqa}; all quantized methods tie on AIME 2025, and BF16 remains strongest overall.

% 表 5 考察基础码字维度带来的质量—码率权衡。
\paragraph{Base-codeword dimension.} Table~\ref{tab:dimension} studies the quality--rate trade-off induced by the base-codeword dimension.
\input{tab/dimension}

% 八维质量最好但码率明显升高；约 2 bpw 时六维是更合适的主设置。
Dimension $d=8$ gives the best quality but increases the rate to 2.59 bpw. Under an approximately 2-bpw budget, $d=6$ provides the stronger trade-off and is therefore our default.
