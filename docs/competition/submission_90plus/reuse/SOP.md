# OpenPrism Office 复用 SOP

## 1. 适用岗位

项目申报负责人、技术/研究材料撰写人、部门材料汇总人、材料审核人和审批负责人。适合需要来源可追溯、多人审阅或对外提交的长文案；不适合无需证据的一次性闲聊。

## 2. 部署与权限

1. 使用受管项目目录保存任务资料，不把凭据、私钥、生产地址放入项目文件。
2. 前端服务绑定 `0.0.0.0`，访问地址和端口由环境变量配置；局域网使用 HTTPS/HTTP 口径由部署方明确。
3. 内置 DOCX/PPTX/XLSX OOXML 读取无需外部服务；OfficeCLI、PDF、OCR、飞书、邮件和 webhook 均为可选能力，未配置时保持 unavailable/blocked。
4. 对外输出必须由人工审批；本地 `published` 只表示工作流状态，不代表外部平台已收到。

## 3. 标准操作

1. **收件**：新建办公交付项目，填写部门、岗位、频率、原流程和交付标准；从项目相对路径导入材料。
2. **处理**：选择本地配方，检查 Office/解析器能力；外部适配器不可用时不要绕过失败态。
3. **审阅**：输入待核验问题，查看 BM25、Vector、Rerank；生成证据关系并处理 support/conflict/missing。
4. **协同**：为关键段落添加评论和修改建议，记录负责人、期限和 provenance；逐条接受或拒绝。
5. **审批**：由指定审批人核对来源、数字、敏感信息和建议决策，然后记录批准事件。
6. **度量**：按每个真实任务记录 baseline、AI、review、retry、setup、maintenance 和质量结果。
7. **交付**：运行证据审核，处理缺失材料和敏感信息提醒；人工勾选确认后导出 submission 包及 manifest。

## 4. 培训与维护

- 首次培训建议 30-45 分钟：10 分钟理解六阶段，15 分钟完成样例，10 分钟讲证据等级和审批边界，其余时间答疑。
- 模板和 Skill 由材料流程负责人维护；权限和部署由系统管理员维护；真实效果数据由业务负责人确认。
- 每月检查一次模板、数据口径、适配器版本和失败案例；重大流程变化后重新录制演示并更新 manifest。

## 5. 成本边界

- 本地解析、检索和证据图不要求外部模型费用。
- AI 草拟、外部 Office 转换、OCR 和协作平台连接可能产生模型、计算、存储或平台费用，部署方必须单独披露。
- 提效测算必须包含人工复核、返工、配置和维护，不只计算模型响应时间。

## 6. 失败与回退

- 材料解析失败：保留 blocked/unavailable 原因，转换为受支持格式或显式配置适配器。
- 证据冲突：不自动选择高值，转人工核验原始材料。
- 缺少来源：将主张标记 missing，不生成不存在的引用。
- 审批未完成：禁止进入 approved/published；不得直接导出为对外正式成果。
- 真实数据不足：只写“Demo 跑通/待试点”，不写稳定提效比例。
