# M04 作品意义

作品名称：OpenPrism Office  
说明口径：本文件说明作品对办公效率、质量、流程治理和数字化建设的意义；不声明未验证的提效比例、真实用户数或获奖结论。

## 1. 对办公效率的意义

办公长文案的耗时通常来自资料定位、事实核验、版本整理、格式交付和反复返工，而不只是初稿写作。OpenPrism Office 的意义在于把这些隐性工作显性化：

1. 来源材料进入项目后被登记、解析和留痕。
2. 关键主张可以通过混合检索回到证据片段。
3. 证据图直接标出支持、冲突和缺口。
4. 人工审批记录保留在工作流中。
5. 导出材料和 manifest 可以作为交付版本依据。
6. 效果测量表把复核、返工、配置和维护都计入。

因此，作品的效率价值不是“让 AI 快速写一段话”，而是减少办公材料从资料到交付之间的重复查找、口径协调和返工沟通。

真实净节省时间需要在 `evidence/E05-effect-measurement.csv` 中补充后才能量化。

## 2. 对质量控制的意义

通用 AI 写作容易产生三类质量风险：

- 没有来源的事实性主张。
- 数字、时间、范围在多份材料中不一致。
- 生成结果被误认为已经人工确认。

OpenPrism Office 的设计把质量控制放在流程中：

| 风险 | 设计应对 |
| --- | --- |
| 无证据主张 | Evidence Index 和 evidence graph 标记 missing |
| 材料冲突 | support/conflict/missing 关系暴露冲突来源 |
| 数字不可复算 | effect measurement 要求基线、AI、复核、返工、配置、维护和样本 |
| 自动发布风险 | human approval required 作为默认边界 |
| 生成物自证 | 禁止 `submission/*` 反向登记为来源 |
| 敏感信息 | 审核阶段提示凭据、个人信息、内部地址和敏感业务信息风险 |

这使作品更适合评审材料、申报材料、制度材料等要求“可追溯、可解释、可复核”的办公场景。

## 3. 对流程治理的意义

传统材料写作往往依赖个人经验，流程不透明。OpenPrism Office 将关键行为落到项目内状态文件：

- `.openprism/office-track.json`：Brief、材料、证据、效果、复用资产和决赛准备。
- `.openprism/office-workspace.json`：收件箱、检索记录、证据图和会议材料。
- `.openprism/office-workflow.json`：连接器、配方、运行时间线、评论、建议、审批和遥测。
- `submission/`：人工确认后的交付材料和 SHA-256 manifest。

这些记录可以帮助团队复盘：哪些证据支撑了结论，哪些建议被采纳或驳回，哪些数据没有补齐，哪些成本被计入，哪些材料版本被导出。

## 4. 对组织复用的意义

本作品把办公材料生产方法沉淀为模板、SOP、Skill、效果表和评审说明，不再只依赖单个作者的经验。

可复用价值包括：

1. 新项目可以从同一模板开始，降低起步成本。
2. 证据等级、审批边界和效果口径保持一致。
3. 评委说明、初赛建议分、决赛准备包的结构固定，减少每次重新组织材料的成本。
4. 复用时明确要求重填 Brief、来源、证据、效果和审批，避免旧结论误用。
5. 可推广到项目申报、技术方案、研究总结、评审说明、会议纪要转汇报等相邻办公场景。

当前复用资产已存在，真实跨用户复用效果仍需补 `evidence/E10-reuse-dry-run.md`。

## 5. 对 AI 应用方式的意义

作品的创新点在于把 AI 从“内容生成器”改造成“受证据和流程约束的办公协作者”：

- AI 或算法可以辅助提炼、检索、审查和生成。
- 系统必须显示来源、分数分解、冲突和缺口。
- 人类仍负责判断、审批和对外提交。
- 没有证据的数据不被自动写成确定事实。
- 效果提升用可复算字段说明，而不是只写主观感受。

这种设计比普通问答或改写更适合办公场景，因为办公材料的核心价值经常取决于准确性、责任边界和可追溯性。

## 6. 对比赛评审的意义

比赛规则要求材料完整性、证据定位、一致性核验、建议分说明和评委材料输出。OpenPrism Office 直接把这些规则产品化：

| 规则要求 | 作品响应 |
| --- | --- |
| 四项必交内容 | 导出 M01 方案、M02 演示脚本、M03 复用说明、M04 作品意义 |
| 效果证明 | 导出 M05，并按全成本口径复算 |
| 标准化资产 | 导出 M06，列出模板、SOP、Prompt/Skill、README |
| 证据定位 | Evidence Index 和 reviewer-guide 记录材料位置 |
| 一致性核验 | audit 输出风险、上限、扣分和置信度 |
| 空白评分表 | 导出 blank-initial-score-sheet |
| 决赛准备 | finals-pack 和 finals-score-guide 维护落地、问答、推广、优化 |

这让作品不仅是一个办公工具，也是一套面向比赛审核规则的材料生产和自审系统。

## 7. 当前边界

本作品意义明确，但提交前仍需诚实补齐以下证据：

1. 真实 3 分钟演示录屏。
2. 至少一组同类任务的基线和使用后全成本耗时。
3. 人工审批和质量核验记录。
4. 脱敏前后输入输出样例。
5. 复用演练或培训记录。
6. 决赛现场问答准备材料。

没有这些数据时，材料只能说明“系统能力已实现、Demo 可跑通、效果待测量”，不能写“已稳定提升若干比例”或“已覆盖若干用户”。
