# E01 场景与原流程基线说明

证据属性：参赛方案中的受控场景分析；尚未由真实部门访谈或生产记录升级为业务事实。

## 目标任务

面向项目申报书、技术方案、研究总结、评审说明和答辩稿等高证据办公长文案。参与角色包括材料撰写人、来源/数据负责人、审阅人和最终审批人。

## 原流程模型

1. 从 Word、PPT、Excel、会议纪要和聊天记录收集资料。
2. 逐份打开文件，复制关键段落和数字到临时笔记。
3. 在另一个文档中起草，手工标来源。
4. 审阅人通过批注或即时通讯提出修改。
5. 撰写人回到源文件查证冲突、缺失和旧口径。
6. 负责人审批后，再手工整理效果表、复用说明和评委材料。

主要负担是跨工具切换、来源回查、冲突处理、审批留痕和提交组包。该模型用于解释新流程减少了哪些环节，不作为人工耗时实测。

## 新流程模型

收件 → 处理 → 审阅 → 审批 → 交付 → 度量。资料、检索、主张关系、建议决策、批准事件、效果字段和导出清单保存在同一项目链路中。

## 待业务核验字段

- 实际岗位和部门；
- 同类任务发生频率；
- 原流程逐任务耗时；
- 错误/返工/审批轮次；
- 真实业务产出及负责人确认。

以上字段进入 `E05-effect-measurement.csv` 前必须来自真实记录。
