# 评委说明写作指南

目标：让评委不用从头翻完所有材料，也能快速判断作品做了什么、证据在哪里、风险是什么、哪些内容还需要人工核验。

## 1. 基本原则

- 先写证据，再写结论。
- 区分“系统自动生成”“参赛方自述”“待补真实证据”。
- 建议分只写成准备度建议，不写成官方分数。
- 缺失数据、材料矛盾和低证据等级要直接写出。
- 不因排版、视频特效或口号感加分。

## 2. 推荐结构

| 章节 | 写作目标 |
| --- | --- |
| 基本信息 | 作品名、赛道、团队、材料完整性、处理提醒、准备度建议分 |
| 一句话说明 | 100 字内说明面向谁、解决什么问题、如何用 AI、产生什么效果、沉淀什么资产 |
| 作者做了什么 | 原流程、新流程、AI 作用、人工责任和最终输出 |
| 核心思想 | 3-5 个真正的设计点，不复述目录 |
| 收益与效果 | 列出基线、使用后、改善幅度、样本、周期和证据 |
| 证据索引 | 每个关键结论对应材料位置和 E0-E3 强度 |
| 材料摘要 | 说明每份材料对评审的价值和缺口 |
| AI 评分摘要 | 四模块建议分、理由、扣分、证据和置信度 |
| 风险与追问 | 数据缺口、材料矛盾、落地风险、敏感信息提醒和决赛问题 |

## 3. 一句话说明模板

```text
作者面向【目标岗位/部门】的【具体办公文案问题】，使用 OpenPrism Office 的【Brief/证据索引/AI 草拟/人工审批/审核导出】流程，重构了【原工作流程】，在【真实测量或待测量范围】内实现了【主要效果或待验证效果】，并沉淀了【模板/SOP/Skill/指标表】等可复用资产。
```

如果没有真实效果数据，把“实现了”改成“计划验证”或“Demo 中观察到”。

## 4. 四模块写法

### 提效成效

必须写：

- 原流程耗时。
- AI 流程耗时。
- 人工复核、重试、配置、维护是否计入。
- 样本量和统计周期。
- 质量是否保持。

缺少数据时写：

> 当前只能证明 Demo 链路跑通和流程步骤减少，尚不能证明稳定平均提效。建议补充同类任务样本、统计周期和质量验收记录。

### 场景价值

必须写：

- 哪个岗位或部门真的会遇到这个问题。
- 发生频率。
- 对质量、成本、响应效率或管理的影响。

避免写：

- “所有办公人员都适用”这类无边界描述。
- 把一次性个人材料包装成组织级高频流程。

### 方案创新性

必须写：

- 证据绑定如何进入写作流程。
- 人工审批门禁如何防止无证据主张。
- 审核和导出如何对应比赛规则。
- 与普通聊天、摘要、改写的差异。

### 可推广性

必须写：

- 模板、SOP、Prompt/Skill、README、FAQ 或培训材料。
- 学习成本、部署条件、权限、成本、维护人。
- 可迁移和不可迁移的边界。

## 5. 证据标注规则

| 来源类型 | 写法 |
| --- | --- |
| Markdown/文档 | 文件名 + 章节标题 |
| 视频 | 文件名 + 起止时间 + 画面内容 |
| 表格 | 文件名 + 工作表/行列范围 |
| 代码 | 文件路径 + 函数/模块 |
| 图片 | 文件名 + 图片编号 + 可见内容 |

证据等级按 E0-E3 标注。E0 只能作为待补，不能支撑关键结论。

## 6. 风险写法

材料处理提醒要写成“提醒人工复核”，不要写成 AI 已经判定违规。

示例：

> 系统发现材料中存在内网 URL 特征，建议提交前人工确认是否需要遮盖。该提醒本身不影响技术评分，除非该地址暴露导致方案无法安全复用。

## 7. 禁止写法

- “AI 评分为最终成绩”。
- “系统判定无造假/无抄袭/无违规”。
- “没有任何风险”。
- “效率提升 80%”但没有原始数据。
- “已稳定落地”但只有演示材料。
