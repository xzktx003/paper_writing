# 真实效果测量协议

本协议用于补齐“提效成效 30 分”的真实证据。没有完成本协议前，提交材料只能写“测量计划”或“Demo 观察”，不能写确定性提效百分比。

## 1. 测量对象

选择同一类办公文案任务，例如：

- 项目申报书初稿。
- 技术方案说明。
- 研究总结。
- 评审说明和答辩稿。
- 会议纪要转正式汇报材料。

前后对比必须保持任务目标、质量要求、材料复杂度和输出格式基本一致。

## 2. 记录字段

| 字段 | 含义 | 是否必填 |
| --- | --- | --- |
| `baselineMinutes` | 原流程完成同类任务耗时 | 是 |
| `aiMinutes` | 使用 AI 和系统操作耗时 | 是 |
| `reviewMinutes` | 人工复核、事实核验和审批耗时 | 是 |
| `retryMinutes` | 失败重试、返工和重生成耗时 | 是 |
| `setupMinutes` | 首次配置、导入资料、模板准备耗时 | 建议填 |
| `maintenanceMinutes` | 复用时更新模板、证据或规则耗时 | 建议填 |
| `sampleSize` | 统计的任务数量 | 是 |
| `measurementStatus` | `designed`、`measured` 或 `verified` | 是 |
| `qualityNotes` | 质量、错误、返工和人工判断说明 | 是 |

系统会把 AI 操作、人工复核、重试、配置和维护都计入成本。不要只比较模型生成时间和人工写作总时间。

## 3. 计算方法

总使用耗时：

```text
totalAiWorkflowMinutes = aiMinutes + reviewMinutes + retryMinutes + setupMinutes + maintenanceMinutes
```

净节省时间：

```text
timeSavedMinutes = baselineMinutes - totalAiWorkflowMinutes
```

净节省比例：

```text
timeSavedRate = timeSavedMinutes / baselineMinutes
```

如果 `setupMinutes` 或 `maintenanceMinutes` 只在首次使用发生，需要在说明中写清是否摊销、摊销到几次任务。没有摊销依据时，不要把它从成本里删掉。

## 4. 质量核验

至少记录以下质量项：

- 无证据主张数量。
- 数字或口径错误数量。
- 人工修改轮次。
- 是否出现敏感信息。
- 是否按目标格式交付。
- 最终是否被业务负责人接受。

提效不能以质量下降为代价。如果速度变快但事实错误、返工增加或审批不通过，必须在 `qualityNotes` 中写明。

## 5. 推荐样本设计

| 阶段 | 最低建议 | 更强证据 |
| --- | --- | --- |
| Demo 验证 | 1 个脱敏任务，完整录屏 | 2 个不同文案类型 |
| 初赛提交 | 3 个以上同类任务，记录完整耗时和质量 | 5-10 个任务，覆盖不同撰写者 |
| 决赛答辩 | 至少一个真实岗位连续使用记录 | 多用户、多周期、可复查业务产出 |

样本不足时可以提交，但应把置信度写成低或中，不要写成稳定平均效果。

## 6. 证据保存

每条效果数据至少关联一种证据：

- 手工计时表或任务日志。
- 系统导出的 `submission/M05-effect-evidence.md`。
- 审批修改记录。
- 最终交付文件和版本记录。
- 脱敏截图或连续录屏。

效果数据进入材料前，数据负责人或业务负责人应人工确认。

## 7. 禁止写法

- “效率提升 80%”但没有基线、样本和计算过程。
- “已经全面落地”但只有单次 Demo。
- “零错误”但没有质量检查记录。
- “无需人工复核”但系统仍要求人工审批。
- 把 AI 根据流程推断的收益写成实测数据。
