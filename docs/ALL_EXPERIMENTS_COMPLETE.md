# 实验完整记录

本文件记录仓库新增实验的目的、方法、参数、结果与结论。结构化结果统一位于 `experiments/results/`；失败或暴露缺陷的步骤同样保留。

## 2026-08-28：具体输入输出、人工前后对照与三分钟成片验证

- **目的**：验证参赛视频能否让评委清楚复述系统接受哪些真实输入、生成哪些具体输出、典型人工原来如何操作，以及效率优势由哪些流程变化产生；同时继续保留六段真实产品操作和无真实样本不报固定提效比例的边界。
- **方法原理**：把讲解扩展为 10 张 PPT 与 6 段实操：开场依次展示典型人工流程、实际输入、目标用户和六步总览；实操右栏固定呈现“典型人工做法/实际输入/实际输出/本步优势”；结尾展示前后流程、五类输出、四项效率机制、真实试点方法和证据边界。用同一 73.76 秒原始录屏裁切功能章节；逐帧检查度量到交付的过渡并冻结最后稳定成功帧。
- **关键参数**：10 张 PPT；6 段实操；16 个叙事章节；57 条字幕；edge-tts `zh-CN-XiaoxiaoNeural`、语速 `+28%`；1920×1080、25 fps、H.264 yuv420p、AAC 48 kHz 双声道；字幕最多 23 字、FontSize 14、120 像素安全区；目标时长 120—180 秒。
- **结果数据**：详细初稿按原语速预计超时，改用画面保留细节、口播去重后成片 165.791 秒。首个剪辑边界让度量章节末尾出现交付页，视觉 88/100；第一次前移又冻结空白过渡帧，视觉 89/100；逐帧检查原录屏 57.5—59.0 秒后，将度量终点锁到 58.0 秒的 `designed` 成功记录，交付从 61.5 秒开始。最终视频 7,058,716 bytes，平均音量 -19.5 dB、峰值 -1.8 dB；视觉裁决 96/100，讲解契约 2/2 通过。
- **结论**：形象讲清办公价值需要把“文件名和类型、状态字段、具体产物、人工旧动作”写到画面和旁白中；效率优势应解释为少搬、少翻、少漏和更易复盘，而不是在无真实试点时给出百分比。功能章节必须按稳定结果帧裁切，不能只按粗略时间戳切段。
- **结构化结果**：`experiments/results/competition_input_output_before_after_video_20260828.json`

## 2026-08-28：PPT 讲解、中文配音与真实实操合成验证

- **目的**：验证参赛视频能否在三分钟内先讲清产品意义、目标用户和功能，再逐步解释六段真实操作的目的与结果，最后总结组合成果、推广方向和证据边界；同时确认讲解字幕是真正随语音定时出现，而不是画面上的静态说明文字。
- **方法原理**：用 Playwright 和仓库随包 Noto Sans SC 渲染 8 张 1920×1080 PPT 讲解页；用 edge-tts `zh-CN-XiaoxiaoNeural` 生成 14 段中文讲解；把 73.76 秒原始连续录屏切为六个功能章节，右侧叠加“为什么做/本步输入/得到什么/证据边界”；把 TTS 时间戳按标点拆成最多 23 字的 SRT，合并全局时间轴并烧录到独立字幕安全区。逐帧抽查开场、总览、六步实操和结尾，并用 ffprobe/volumedetect 检查媒体。
- **关键参数**：8 张 PPT；6 段实操；14 个叙事章节；50 条字幕；1920×1080；25 fps；H.264 yuv420p；AAC 48 kHz 双声道；edge-tts 语速 `+18%`；最终 loudnorm 目标 I=-16/TP=-1.5；字幕 libass 字号 14、底边距 10；目标时长 120—180 秒。
- **结果数据**：首轮 14 段自然语速预计超过 180 秒，压缩重复讲稿后成片 150.424 秒。视觉首轮因字体内部名称不匹配出现中文方框；改为 `Noto Sans SC Thin` 后中文恢复，但 34 号 SRT 字幕被 libass 内部画布放大并遮挡实操；按实测比例改为 14 号、底边距 10 后，字幕稳定落入 120 像素安全区。最终视频 6,635,894 bytes，H.264 1920×1080 yuv420p + AAC 48 kHz 双声道，平均音量 -19.5 dB、峰值 -1.5 dB；移除模板化单侧粗色条后视觉裁决 94/100，讲解视频契约 2/2 通过。
- **结论**：讲解型参赛视频应把语音、逐句字幕和画面解释分成三个层次；宏观 PPT 与真实操作穿插能比单纯录屏更完整地说明办公价值。字幕必须使用字体真实内部名称并以最终抽帧而非参数直觉判断大小。成片仍只证明技术闭环和受控演示，不替代真实企业试点。
- **结构化结果**：`experiments/results/competition_narrated_presentation_video_20260828.json`

## 2026-08-28：参赛视频中文烧录字幕兼容性

- **目的**：验证在宿主系统没有中文字体时，FFmpeg/libass 仍能稳定生成中文可读、三分钟内、平台兼容的参赛成片。
- **方法原理**：先直接把前端随包 WOFF2 字体交给 libass，保留中文方框的失败结果；再用已安装的 fontTools 将同一字体临时解包为 TTF，供 libass 烧录 ASS 字幕。最终从片头、收件、审阅、度量、交付和片尾六个时间点抽帧目检，并用 ffprobe 验证媒体参数。
- **关键参数**：原始 H.264 73.760 秒；片头 5 秒；片尾 7 秒；25 fps；1440×960；libx264 CRF 20、medium、yuv420p、faststart；字幕底板使用半透明深色不透明框；输出无音轨。
- **结果数据**：直接加载 WOFF2 时中文显示方框；转换为 TTF 后片头、处理、度量、交付和片尾抽检画面中文均正常。最终成片 85.760 秒，H.264、1440×960、yuv420p，小于 3 分钟；同时生成 ASS、逐段解说词稿和 JPG 封面。
- **结论**：参赛视频构建不能依赖宿主字体，也不能直接假设 libass 支持 WOFF2；构建脚本应临时转换仓库已随前端分发的字体，结束后清理临时文件。成片只增加说明层，不裁断中间的连续操作证据。
- **结构化结果**：`experiments/results/competition_video_subtitle_render_20260828.json`

## 2026-08-28：参赛演示多帧功能覆盖与失败即停验证

- **目的**：修复旧演示“每阶段只有一张截图、OfficeCLI 主画面失败、成功结果与风险边界未完整入镜”的问题，验证新版材料能否用连续证据证明每个主要功能真实成功。
- **方法原理**：把六阶段拆成输入、计划/执行、结果、人工决策和风险边界等 19 个状态；脚本对 OfficeCLI `ok / validate`、DOCX ready、会议决定/待办、support/conflict/missing、accepted、approved、published、designed、94/100 和导出文件逐项断言，任何断言失败立即终止。第一次运行因反证文本仍被判为 support 而失败，调整为与共享动作词局部否定匹配的受控反证后重跑。视觉验收又发现度量边界和审核总分滚出视口，修正取景锚点后再次完整重录。
- **关键参数**：OfficeCLI 1.0.145；SHA-256 `449f0e6a1298e3c6d7da792d26ab53d04ba77bd990f299b51123c7aef383d2ce`；6 阶段；19 张 1440×960 截图；每阶段至少 2 张；每张大于 50 KB；视觉通过阈值 90。
- **结果数据**：6/6 阶段为 success，OfficeCLI 状态 ok，证据图同时出现 support/conflict/missing；5/5 演示契约测试通过；视觉验收 94/100；原始视频 73.760 秒，提交成片 85.760 秒。
- **结论**：新版主演示不再包含主要功能失败画面，且单一功能通过多张截图形成输入—执行—结果证据链。真实企业多用户/多周期提效和非作者独立复现仍未发生，不能由技术演示替代。
- **结构化结果**：`experiments/results/competition_demo_v2_coverage_20260828.json`

## 2026-08-27：OfficeCLI v1.0.145 真实二进制适配验证

- **目的**：确认 GitHub 上游 OfficeCLI 的真实命令合同、Linux 二进制完整性，以及 OpenPrism 的安全 argv 适配器能否创建、读取、修改、模板合并、验证和渲染 Office 文件。
- **方法原理**：从 `iOfficeAI/OfficeCLI` v1.0.145 release 下载 Linux x64 资产与 `SHA256SUMS`，先校验哈希，再读取 `--version`/各命令 `--help`。使用 `OFFICECLI_SKIP_UPDATE=1` 运行 OpenPrism 适配器，并用内置 OOXML 解析器交叉读取生成物。
- **关键参数**：版本 `1.0.145`；资产 SHA-256 `449f0e6a1298e3c6d7da792d26ab53d04ba77bd990f299b51123c7aef383d2ce`；操作 `dump/create/batch/merge/view/validate`；执行 `shell: false`；临时样本位于 `/tmp` 且未提交。
- **结果数据**：checksum 与 release 清单一致；`--version` 返回 `1.0.145`；create/dump/validate/view HTML、batch edit、template merge 均成功。创建 DOCX 5,183 bytes，dump JSON 7,924 bytes，HTML 49,376 bytes。首次交叉读取 merge DOCX 时暴露 `xml:space="preserve"` 文本漏读，修复解析器后读回“可核验办公方案”。
- **结论**：适配器应固定映射上游真实命令，不能推测不存在的 `diff`；OpenPrism 保留内置抽取文本 diff。OfficeCLI 可作为显式可选能力，不应作为默认依赖或在运行中自动更新。
- **结构化结果**：`experiments/results/officecli_v1_0_145_smoke.json`

## 2026-08-27：中文组合证据支持/冲突判定

- **目的**：验证一段中文办公材料同时包含肯定事实和另一项否定结果时，不会将所有相关主张统一误判为冲突。
- **方法原理**：用“试点已批准，但首次演练未减少材料整理耗时”作为唯一材料，分别查询批准主张与耗时下降主张；冲突必须绑定共享动作词附近的局部前置否定。
- **关键参数**：本地 BM25 + 128 维哈希 token/字符 n-gram 余弦 + deterministic reranker；证据图 topK 使用默认值。
- **结果数据**：批准主张产生 `support`，耗时下降主张产生 `conflict`；独立中文材料、组合段落单测与真实路由 E2E 均通过。
- **结论**：整段 conflict marker 只能作为候选信号，不能替代面向主张的局部否定判断。
- **结构化结果**：`experiments/results/chinese_evidence_relation_regression.json`

## 2026-08-27：办公赛道受控证据链复现评估

- **目的**：为参赛材料提供不依赖主观描述的技术证据，验证中文材料检索、支持/冲突/缺失关系、会议决定/待办提取和重复运行稳定性，同时明确该实验不替代真实业务提效试点。
- **方法原理**：构造 4 份脱敏受控材料、4 个检索问题、4 个证据主张和 1 份带时间戳逐字稿；使用本地 BM25 + 128 维哈希向量 + deterministic reranker、证据关系图和会议解析器运行 100 次，并保存原始 JSON。
- **关键参数**：chunk size 80、overlap 10、search topK 3、graph topK 4、重复 100 次；Node/平台信息随结果保存，但不记录主机路径、凭据或业务敏感数据。
- **结果数据**：首次运行 9 项检查通过 8 项，暴露“没有证明稳定提效”被误判为 support；补充红灯测试并修复否定动作词后，9/9 通过。最终 100 次重复运行的 p50、p95、max 延迟以结果 JSON 为准。
- **结论**：当前实现能在受控样本中可复现地区分 support/conflict/missing 并提取时间戳决定/待办；这些结果只证明技术正确性和演示可复现性，不得写成企业生产率或稳定真实落地。
- **结构化结果**：`experiments/results/office_competition_controlled_evaluation_20260827.json`
