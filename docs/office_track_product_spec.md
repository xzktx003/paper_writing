# OpenPrism Office 产品改造规格

日期：2026-08-27

## 1. 目标

把现有 Paper Agent 的本地项目、AI、Skills、RAG、审查、Diff、Pipeline 和编译能力，收敛为一条面向办公长文案的可核验交付流程。主要用户是科研管理、技术管理、项目申报和知识密集型办公岗位。

目标不是“让 AI 随便写得更快”，而是让一份材料的问题定义、来源、主张、数字、修订、审批、交付和提效证据可追溯、可复算、可复用。

## 2. 一条权威工作流

```text
新建办公材料项目
  → 填写任务 Brief 与不可改变的边界
  → 登记并检查来源材料
  → 建立证据索引
  → 选择业务 Skill 起草
  → 审查无依据声明、数字、矛盾与敏感信息
  → 通过 Diff / 明确动作人工采纳
  → 生成 PDF/Markdown 交付件
  → 记录基线、实际耗时、质量与额外成本
  → 导出交付包、证据索引、SOP 和评审说明
```

## 3. 核心数据对象

### 3.1 Office Brief

- 作品/任务名称、材料类型、目标岗位和部门；
- 真实问题、发生频率、原流程、主要痛点和交付标准；
- 不能改变的事实、语气、审批人、截止时间、权限和敏感级别；
- AI 介入点、人工责任和已知依赖。

### 3.2 Material Registry

每份材料拥有稳定编号、类型、项目相对路径、版本、可读状态、脱敏状态、用途和备注。比赛提交默认识别 M01—M06，但数据模型不绑定比赛。

### 3.3 Evidence Index

每条证据记录：

- 编号、所支持的结论、来源材料编号；
- 精确位置（页码/章节/时间戳/工作表/代码符号）、证据摘要；
- E0—E3 强度、核验状态、核验人、最后核验时间；
- 是材料明载、流程推断还是尚待确认。

### 3.4 Effect Measurement

每个指标记录基线值、实际值、单位、样本量、统计周期、计算过程、使用频率和覆盖人数。`reviewIncluded`、`retryIncluded`、`setupIncluded` 和 `maintenanceIncluded` 明确说明是否纳入隐性成本。

### 3.5 Reusable Asset

记录 SOP、Prompt/Skill、模板、代码/工具包、README、FAQ、培训材料、部署和维护说明，并标记目标岗位、学习成本、权限和复现状态。

## 4. 正式 UI

### 4.1 项目首页

- 产品标识收敛为 OpenPrism Office / 可核验的 AI 办公材料工作台。
- 新建项目提供办公材料模板与学术模板分类，默认引导用户填写 Brief，不默认伪造效果数据。

### 4.2 正式工作台

在右侧正式 React 工作台增加“交付”面板，而不是打开 Legacy 原型。面板按交付阶段组织：

1. Brief；
2. 材料；
3. 证据；
4. 数据与效果；
5. 复用资产；
6. 审核与导出。

面板顶部显示不造假的就绪状态：已验证、待补充、需人工复核、材料处理提醒。不用一个绿色分数遮蔽缺口。

## 5. 后端边界

- 状态保存在项目内 `.openprism/office-track.json`，通过 managed `projectId` 和 `safeJoin` 访问；
- 导出产物写入用户可见的 `submission/`，不包含凭据、绝对路径和未脱敏源文；
- 所有写入都使用临时文件 + rename 原子替换；
- 用户输入必须限长、枚举值校验、路径校验，禁止 shell 拼接；
- 审核只生成建议和证据，不自动作出取消资格、晋级或造假结论。

## 6. 导出产物

`submission/` 最低包含：

- `M01-proposal.md`；
- `M02-demo-script.md`；
- `M03-reuse-statement.md`；
- `M04-significance.md`；
- `M05-effect-evidence.md`；
- `M06-reuse-assets.md`；
- `reviewer-guide.md`；
- `initial-score-guide.md` 与 `blank-initial-score-sheet.md`；
- `finals-pack.md` 与 `finals-score-guide.md`；
- `submission-manifest.json`，包含文件 SHA-256、生成时间、规则版本和未解决缺口。

登记的原始材料与证据不得指向上述生成文件，避免导出覆盖来源或让生成结果反过来冒充原始证据。推荐把来源放在 `sources/`、`evidence/`、`metrics/` 与 `reuse/`。

## 7. 红绿灯验收

1. 无状态时 GET 返回稳定 schema 和“待补充”，不偷偷写文件；
2. 保存会拒绝越界路径、非枚举状态、非有限数字、过长文本和未知字段；
3. 没有四项必交材料或演示时返回“待补充”，不形成伪正式分；
4. 前后任务口径不同、数据矛盾或计算不可复算时降低可信度并转人工复核；
5. 不存在证据的结论标为“参赛方自述”，不自动升级为已验证；
6. 导出必须为幂等原子写入，manifest hash 与真实文件一致；
7. 正式 React UI 在桌面和 390×844 上都能完成 Brief 保存、证据登记、指标填写、审核和导出；
8. 未配置模型时仍能手工完成上述记录和导出；
9. 无 Token 时新 API 与导出文件全部 fail-closed；
10. 功能清单、README、规则矩阵、测试和产品实现在同一提交中同步。
